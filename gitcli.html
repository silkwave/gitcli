1. Git 기본 설정

Git을 처음 사용하거나 로컬 환경을 구성할 때 유용한 명령어들입니다.

# Git이 사용할 기본 편집기 지정 (VSCode 추천)
git config --global core.editor "code --wait"
# git config --global core.editor "notepad"
# git config --global core.editor "nano"

# Git 인증 정보 저장 방식 설정
# 1. OS 인증 관리자 사용 (추천, 안전)
git config --global credential.helper manager
# 2. 평문 파일로 저장 (비추천, 보안 취약)
# git config --global credential.helper store
# git config --global --unset credential.helper # 설정 해제

# Git 출력 화면 Pager 비활성화 (긴 로그 전체 출력)
git config --global core.pager cat

# WSL 사용 시, 다른 OS의 파일 시스템에 있는 저장소를 안전하게 처리하도록 설정
git config --global --add safe.directory '*'

2. 한글 환경 설정

Git 사용 시 터미널이나 커밋 로그에서 한글이 깨지는 현상을 방지합니다.

3. 일반적인 작업 흐름

일상적인 Git 버전 관리 작업의 표준 순서 예시입니다.

# 1. 원격 저장소의 최신 변경사항을 가져옴
git fetch --all --prune

# 2. 현재 작업 디렉토리의 상태를 확인
git status

# 3. 원격 'dev' 브랜치의 변경사항을 현재 브랜치로 가져와 통합
git pull origin dev

# 4. 변경된 모든 파일을 스테이징
git add .

# 5. 스테이징된 파일들을 커밋
T=$(date "+%Y-%m-%d %H:%M:%S");
S=$(git status -s | head -n 1);
git commit -m "자동 커밋 - $T: $S";

# 6. 로컬 커밋을 원격 'dev' 브랜치에 푸시
git push origin dev

4. 커밋 및 브랜치 되돌리기

4.1. 특정 커밋 되돌리기

  • git reset --soft HEAD~1: 마지막 커밋을 취소합니다. 변경 내용은 Staging Area에 보존됩니다.
  • git reset --mixed HEAD~1: 마지막 커밋과 스테이징을 함께 취소합니다. 변경 내용은 Working Directory에 보존됩니다.
  • git reset --hard <commit_hash>: 특정 커밋 시점으로 완전히 되돌아갑니다. 이후의 모든 변경 이력이 삭제되므로 주의해야 합니다.

4.2. 로컬 브랜치를 원격 브랜치 상태로 강제 초기화

로컬의 모든 변경사항을 버리고 원격 브랜치 상태로 덮어쓰는 작업입니다.
git fetch origin
git reset --hard origin/main

4.3. reset --hard 복구하기

  • git reflog: HEAD의 지난 기록들을 확인합니다.
  • git reset --hard HEAD@{1}: 돌아가고 싶은 시점으로 다시 강제 이동합니다.
  • git branch backup-before-reset: 복구 작업 전 현재 상태를 백업 브랜치로 만들어 둘 수 있습니다.

5. 브랜치 관리

# 모든 로컬 및 원격 브랜치 목록을 표시
git branch -a

# 원격 'dev' 브랜치를 기반으로 로컬에 브랜치 생성 후 전환
git switch -c feature-task origin/dev

# 현재 로컬 브랜치가 특정 원격 브랜치를 추적하도록 설정
git branch --set-upstream-to=origin/dev

# 각 로컬 브랜치가 어떤 원격 브랜치를 추적하고 있는지 확인
git branch -vv

# 모든 브랜치의 추적 관계만 간단히 확인
git for-each-ref --format="%(refname:short) -> %(upstream:short)" refs/heads/

# 로컬 브랜치 삭제
git branch -d <branch_name>
git branch -D <branch_name>

# 원격 브랜치 삭제
git push origin --delete <branch_name>

# 두 브랜치 간의 코드 차이점을 비교
git diff <branch1>..<branch2>

5.1. 로컬 브랜치를 다른 이름의 원격 브랜치로 푸시

# 사용법: git push --set-upstream <원격저장소> <로컬브랜치>:<원격브랜치>
git push --set-upstream origin dev_silkwave:dev

6. 원격 저장소

# 등록된 모든 원격 저장소의 이름과 URL을 확인
git remote -v

# 'origin' 원격 저장소의 URL을 확인
git remote get-url origin

# 'origin' 원격 저장소의 URL을 변경
git remote set-url origin https://github.com/user/repo.git

# SSH 주소로 변경 및 접속 테스트
# git remote set-url origin git@github.com:user/repo.git
# ssh -T git@github.com

# 현재 Git 저장소의 원격 URL을 웹 브라우저로 열기
git_repo_url=$(git config --get remote.origin.url | sed 's/git@/https:\/\//; s/:/\//; s/\.git$//')
start "$git_repo_url"      # windows
wslview "$git_repo_url"    # wsl2

7. Stash (임시 저장)

현재 작업 내용을 커밋하지 않고 잠시 다른 브랜치로 이동해야 할 때 변경사항을 임시로 저장합니다.

# 현재 변경사항을 메시지와 함께 스태시에 저장
git stash push -m "WIP: 작업 내용 임시 저장"

# 스태시 목록 확인
git stash list

# 가장 최근의 스태시를 적용하고 목록에서 삭제
git stash pop

# 가장 최근의 스태시를 적용하되 목록에는 유지
git stash apply

8. Git 동기화 상태 및 해결 방법

  • Your branch is up to date with 'origin/dev'. 로컬과 원격 브랜치가 완전히 동일합니다.
  • Your branch is ahead of 'origin/dev' by N commits. 로컬 브랜치에만 존재하는 커밋이 있으므로 git push로 반영합니다.
  • Your branch is behind 'origin/dev' by N commits. 원격 브랜치에만 존재하는 커밋이 있으므로 git pull로 가져옵니다.
  • Your branch and 'origin/dev' have diverged. 로컬과 원격이 서로 다른 커밋 히스토리를 가지고 있으므로 병합 또는 리베이스 전략을 선택합니다.

8.1. 추가적인 동기화 상태 확인

# 각 브랜치의 추적 상태와 원격과의 커밋 차이 확인
git branch -vv

# 로컬과 원격 브랜치의 커밋 히스토리를 그래프 형태로 비교
git log --graph --oneline main...origin/main

8.2. 다양한 Pull 및 Rebase 전략

# Merge 방식
git pull origin main
git pull --no-ff origin main

# Rebase 방식
git pull --rebase origin main

# 수동 Rebase
git fetch origin
git rebase origin/main

# Rebase 중단
git rebase --abort

9. Git 충돌 해결

  1. 충돌 파일 확인: git status로 어떤 파일에서 충돌이 발생했는지 확인합니다.
  2. 파일 수정: 편집기로 충돌 파일을 열어 충돌 구간을 정리합니다.
  3. 파일 스테이징: 수정 완료된 파일을 git add 합니다.
  4. 커밋: 병합 커밋을 완료합니다.
  5. 푸시: 해결된 내용을 원격 저장소에 푸시합니다.
<<<<<<< HEAD
(A: 현재 브랜치의 변경 내용)
=======
(B: 병합하려는 브랜치의 변경 내용)
>>>>>>> some-branch-name
git add <충돌_해결한_파일명>
git commit
git push

9.1. 고급 충돌 해결

# 원격(Theirs) 버전으로 덮어쓰기
git restore --source=theirs <path/to/file>
git add <path/to/file>
git commit -m "chore: Resolve conflict by accepting theirs"

# 로컬(Ours) 버전으로 덮어쓰기
git restore --source=ours <path/to/file>
git add <path/to/file>
git commit -m "chore: Resolve conflict by accepting ours"

# 특정 브랜치에서 단일 파일 복원
git fetch origin
git restore --source=origin/dev -- <path/to/file>
git add <path/to/file>
git commit -m "chore: Restore file from origin/dev"

# 특정 브랜치로 전체 디렉토리 복원
git restore --source=origin/main -- .
git restore --source=origin/main --staged --worktree -- .

10. 줄바꿈(LF ↔ CRLF) 문제

증상: 수정하지 않은 파일이 변경된 것으로 인식되거나 pull, merge 시 불필요한 충돌이 발생합니다.

10.1. 확인 방법

# 현재 Git 설정 확인
git config --global core.autocrlf
git config core.autocrlf

# 줄바꿈 문자로 인한 잠재적 문제 검사
git diff --check

10.2. 권장 설정

  • Windows: git config --global core.autocrlf true
  • Mac/Linux: git config --global core.autocrlf input

.gitattributes 예시

# 모든 텍스트 파일의 줄바꿈을 Git 내부에서 자동으로 정규화(LF)
* text=auto

# 특정 확장자는 항상 LF로 유지
*.sh text eol=lf
*.py text eol=lf

# Windows용 배치 파일은 CRLF로 유지
*.bat text eol=crlf

10.3. 저장소의 모든 파일 줄바꿈 정규화

# .gitattributes 파일 추가 및 커밋
echo "* text=auto" >> .gitattributes
git add .gitattributes
git commit -m "chore: add .gitattributes for line endings"

# 모든 파일의 줄바꿈을 규칙에 맞게 재정규화
git add --renormalize .
git commit -m "chore: normalize line endings"

# 대체 방법: Git 캐시를 비우고 다시 체크아웃
git rm --cached -r .
git reset --hard

10.4. 임시 회피책

git stash push -u
git pull --rebase
git stash pop
개인 PC에서는 core.autocrlf를 OS에 맞게 설정하고, 협업 프로젝트에서는 .gitattributes 파일로 줄바꿈 규칙을 명시하는 것이 좋습니다.

11. 고급 스킬 및 유용한 팁

11.1. 대화형 스테이징

git add -p
# 또는
git add --patch

명령을 실행하면 Git이 변경된 각 부분을 보여주며 스테이징 여부를 대화형으로 묻습니다.

11.2. 최신 명령어로 브랜치/파일 관리

# 브랜치 전환
git switch feature

# 브랜치를 생성하고 즉시 전환
git switch -c feature

# Working Directory의 파일 변경사항 취소
git restore <file_name>

# Staging Area에 있는 파일을 Unstage
git restore --staged <file_name>

11.3. 브랜치 정리

# 현재 브랜치에 완전히 병합된 로컬 브랜치 목록 보기
git branch --merged

# 현재 브랜치에 아직 병합되지 않은 로컬 브랜치 목록 보기
git branch --no-merged

# 설정된 원격 추적 브랜치 관계 제거
git branch --unset-upstream

11.4. 작업 디렉토리 정리

# 어떤 파일과 디렉토리가 삭제될지 미리 확인
git clean -fdn

# 실제로 추적되지 않는 파일 및 디렉토리를 삭제
git clean -fd

11.5. 특정 커밋 내용 상세 보기

# 가장 최근 커밋의 상세 정보 보기
git show

# 특정 커밋의 상세 정보 보기
git show <commit_hash>

11.6. Git 별칭 설정하기

git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.ci commit
git config --global alias.st status
git config --global alias.hist "log --graph --pretty=format:'%C(yellow)%h%Creset %C(cyan)%d%Creset %s %C(bold green)(%cr)%Creset %C(blue)<%an>%Creset'"

git st는 git status와 동일하게 동작하며, git hist로 보기 좋게 꾸며진 로그를 출력할 수 있습니다.
